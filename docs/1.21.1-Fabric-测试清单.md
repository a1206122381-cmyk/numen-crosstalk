## 三、关于方案 A 的结论：**不可行，已走 B**

你的要求是"先测 A，分不清就 B"。**我查证后确认 A 不可行**，理由是协议层的：

> **MCP 协议里没有「谁在调用」这个字段。**
> 工具调用只带工具名和参数。外部 MCP 服务器无法分辨是 Lin 在说还是 Wei 在说。

而 mod 里的工具调用**天然带身份**：

```java
call.ctx()              // → ToolAnchor
    .entityUuid()       // → 发起这次调用的同伴 UUID
```

**这不是实现细节，是架构差异。** 所以直接走了 B。

### 顺带发现的 1.21.1 与 1.20.1 的差异

| | 1.20.1 Forge（旧） | 1.21.1 Fabric（新） |
|---|---|---|
| 同伴载体 | 服务端假玩家 | **客户端 mod** |
| 新 API | `NumenPlugins` | **`NumenGateway`** + `NumenApi` |
| 说话 | ❌ 内置大脑没有 say 工具 | `NumenActuator.say()` 存在，但同样只到主人屏幕 |
| MCP 客户端 | 需自己写 | ✅ **内置**（设置里有 MCP 页） |

## 四、写出来的 mod：`numen-crosstalk-fabric`

### 三个工具

| 工具 | 作用 | residency |
|---|---|---|
| `say(text, urgent)` | 说一句，让这里的人听得见。`urgent` 会打断对方 | RESIDENT |
| `hear(mark_read)` | 听自上次以来别人说了什么 | RESIDENT |
| `who_is_here()` | 看有谁在 | RESIDENT |

### 关键实现点

**① 身份可靠**（这是选 B 的全部理由）

```java
UUID id = call.ctx().entityUuid();   // 发起调用的同伴
```

**② 非身体工具要覆写 `invoke`，不是 `onServerCall`**

Numen 的 `NumenTool` 文档写得很清楚：`onServerCall` 是**身体工具**的路径
（动同伴身体、读它的世界，调用要发往服务端活体）。
说话和听不是身体动作——它们读写共享文件，和内置的 `todowrite` 同类。

**③ 队列格式与 `speech-mcp` 完全一致**

两边读写同一批文件（`speech.jsonl` / `heard.jsonl` / `heard-cursor.json`），
但**互不知道对方存在**。这个边界让任何一端都能被替换。

**④ 游标记「序号」不记「行号」**

1.20.1 那版踩过的坑：文件末尾换行让 `split("\n")` 多出一个空元素，
游标被推到文件实际行数之外，之后所有新消息都被当成"已读"——
表现成 `hear()` 永远听不到东西。

**⑤ 处理「队列被换掉」**

换存档/清空队列时 `seq` 从头开始，旧游标（比如 400）比新队列最大 seq（比如 2）还大
→ 所有消息都被当成已读。判据：游标 > 最大 seq 即判定重置。

**⑥ 工作目录是 `config/crosstalk/`**

不放在存档里。这几个文件是"管道"不是世界状态——
换世界时队列跟着换反而会让游标错位。

## 五、踩到的构建坑（值得记下来）

### 坑：Numen 的制品用 intermediary 名且没有 refmap

```java
// 这个 jar 里：
public static net.minecraft.class_742 resolve(java.util.UUID);
//                    ↑ 不是 AbstractClientPlayer
```

作者没有按标准 Loom 流程发布，带来两个连锁问题：

| 做法 | 结果 |
|---|---|
| `modImplementation` 依赖 | Loom 当 remap 过的制品再处理一遍 → 运行期类名对不上 |
| 代码里 `import ...AbstractClientPlayer` 强转 | 编译期 Mojang 名，运行期不是 → 失败 |
| 直接写 `ClientNumenLookup.resolve(id)` | **javac 为确认调用必须加载返回类型** → `cannot access class_742`，哪怕从不碰返回值 |
| 解压 sources 一起编译 | 源码里就是 `class_742`，开发环境没那个类 |

**最终解法**：本 mod **不引用任何 Minecraft 类型**，需要什么用反射按名字找。

好在**身份那条主路径是干净的**——`ToolAnchor.entityUuid()` 只返回 `UUID`，
所以最核心的功能不依赖反射。

### 代价

`libs/` 里要放一份 API jar（1.29 MB）供编译期确认签名。
**运行期不需要它**——玩家的 mods 目录里本来就有。

   名字会退化成 UUID 前 8 位（功能仍可用，只是难看）。看日志里的 debug 行。

3. **`RESIDENT` residency 是否合适** —— 如果三个工具每轮都占位置导致上下文压力，
   可以改成 `DEFERRED`。
4. **多只同伴并发写 `speech.jsonl`** —— 加了 `synchronized`，但没实测过并发。
