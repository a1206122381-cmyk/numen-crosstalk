# 实测发现：`who_is_here` 说错话（已修）

---

## 一、现象

你和 AAA 的对话：

```
你：  跟Dva说句话，评价一下她的皮肤好不好看
AAA： [who_is_here] → "(nobody else)"
AAA： Dva 现在不在这个世界里,我刚看了下,这里就我一个。

你：  你确定吗？
AAA： [who_is_here] → "(nobody else)"
AAA： 确定,我又看了一遍,这世界现在只有我一个,Dva 不在这里。
```

**AAA 连查两次，两次都自信地说"只有我一个"——而 Dva 就在世界里。**

---

## 二、根因：**反射方法名猜错了，然后静默降级**

`who_is_here` 的实现有两条路：

```
路 1  世界玩家列表 → 权威，但靠反射（名字可能不对）
路 2  同伴目录     → 只含同伴，且可能是休眠的
路 3  队列反推     → 只含"最近说过话的人"（Dva 没说过话 → 空）
```

**实际发生的事**：

| 步骤 | 结果 |
|---|---|
| 路 1 反射调用 | ❌ 方法名不对，抛异常，被 catch 吞掉 |
| 路 2 `known()` | 返回了 UUID，但名字解析也失败 → 空 |
| 路 3 队列 | 空（Dva 没说过话） |
| **最终回答** | **`(nobody else)`** |

**关键错误是我的**：路 1 失败时，我让代码掉进路 3，
而路 3 回答的是"**谁最近说过话**"——**不是"谁在这里"**。

这两件事被混为一谈，工具就理直气壮地说错话了。

---

## 三、为什么这个 bug 特别糟

**它不是崩溃，是自信地说错。**

- 崩溃会被发现
- 说错话会被**当成事实**——AAA 据此推断"Dva 不在线"，还给出了行动建议
  （"等她上线我再说"）

而且它**连问两次都答错**，因此更加确信。

> **工具在不确定时应该说"我不知道"，而不是编一个确定的答案。**

---

## 四、修了什么

### 4.1 区分「查不到」和「确认没人」

```
之前：查不到 → 空列表 → "(nobody else)"     ← 撒谎
现在：查不到 → Source.NONE → 报错"读不到名单"  ← 诚实
```

### 4.2 把"谁在线"和"谁说过话"分开

| 来源 | 含义 | 标注 |
|---|---|---|
| `Source.WORLD` | 权威在线名单 | 不标注 |
| `Source.COMPANION_DIRS` | 同伴目录（**可能含休眠的**） | 如实标注这个差别 |
| `Source.NONE` | 查不到 | **报错** |

### 4.3 反射改成多路尝试

方法名在不同版本会变（`players()` / `getPlayers()` / `playerEntities()`…），
所以按候选名依次试，而且**把用了哪条写进日志**——下次不用再猜。

```
[crosstalk] who_is_here：从世界实体列表读到 2 个人
```

## 五、顺带纠正我一个判断

我先前根据"日志里 Dva 只有 1 条记录"推断她是**休眠**的。

**这个推断错了**——后来日志里出现：

```
[numen-skin] 借到 Dva 的皮肤
```

**换皮肤需要她存在**，说明她是活的。

所以真相是：**Dva 好好地在世界里，只是 `who_is_here` 查不到她。**
